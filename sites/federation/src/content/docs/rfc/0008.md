## Summary

This RFC will define the transport protocol, discovery mechanism, and operational behavior for the AEGIS Governance Federation Network (GFN-1): the layer that enables multiple AEGIS governance nodes to share intelligence, policy updates, and attestations.

---

## Status Note

This is a placeholder RFC. Content is pending. The RFC number is reserved to maintain index continuity with the federation specification series.

The current GFN-1 specification leverages [AT Protocol](https://atproto.com) for federation primitives (DIDs, signed records, firehose, relay). RFC-0008 is reserved to formalize:

- AT Protocol Lexicon mappings for each governance event type
- Feed generator interface (extending `app.bsky.feed.generator`) for governance feeds
- Discovery mechanism for federation nodes (well-known endpoints, DID document service entries)
- Cross-organization federation considerations (multi-network, consortium-scoped routing)
- Optional integrations: A2A (Agent-to-Agent) for direct queries against node state, MCP (Model Context Protocol) bindings

The governance event envelope and payload schemas are already defined in [RFC-0004](/rfc/0004/) and [Event Schemas](/spec/schema/). RFC-0008 covers the transport and operational layer above those envelopes.

## Anticipated Topics

- GFN-1 node discovery and peering
- AT Protocol Lexicon registry for `governance.*` event types
- Federation topology models (hub-and-spoke, mesh, hierarchical, consortium-private)
- Node identity and trust bootstrapping over the wire
- Policy propagation guarantees and consistency model
- Compromised node detection and isolation
- Cross-organization federation considerations
- Optional A2A integration for direct agent queries about federation state
